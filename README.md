보석을 모아 개발 카드를 사고, 카드로 다음 카드를 깎고, 귀족을 불러 15점을 먼저 넘기는 게임.
방 코드나 초대 링크로 최대 4인이 붙는다. 온라인 판은 서버(Cloudflare Workers + Durable Object)가 심판을 맡고,
혼자 하기(봇과)는 서버를 거치지 않고 브라우저에서 돈다. 계정은 없다.

## 규칙

- **보석 5종** — 다이아몬드 · 사파이어 · 에메랄드 · 루비 · 오닉스. 여기에 아무 색으로나 쓰는 **황금**.
  칩은 2인 4개씩, 3인 5개씩, 4인 7개씩 깔고 황금은 인원과 무관하게 항상 5개다.
- **개발 카드 90장** — 1단계 40 / 2단계 30 / 3단계 20. 단계마다 4장씩 펼쳐 놓는다.
- **귀족** 은 인원 +1명을 뽑아 깔아 둔다. 전부 3점.

차례에 **셋 중 하나**만 한다.

- 서로 다른 보석 **3개**를 하나씩 집기
- 같은 보석 **2개** 집기 — 그 보석이 **4개 이상** 남아 있을 때만
- 펼쳐진 카드나 내 킵 카드 **사기**
- 카드 한 장 **킵**하고 황금 1개 받기 — 킵은 3장까지, 더미에서 안 보고 가져올 수도 있다

카드를 사면 그 색 보석 하나를 **영구히** 대신한다. 카드가 쌓일수록 다음 카드가 싸진다.
**칩은 10개까지**. 넘기면 넘친 만큼 그 자리에서 버린다.
귀족은 카드 색깔 수가 조건을 채우면 **차례를 쓰지 않고** 저절로 온다. 다만 **한 턴에 한 명**만.

15점을 넘긴 사람이 나와도 거기서 끝나지 않는다. **그 라운드의 마지막 사람까지** 차례를 마치고,
가장 높은 점수가 이긴다. 동점이면 **개발 카드가 적은 사람**, 그 다음 귀족 수, 남은 칩 수,
그래도 같으면 후공이 이긴다.

### 카드 구성

다섯 색이 정확히 대칭이다. 어떤 카드도 **자기 색을 요구하지 않는다.**

| 단계 | 색당 장수 | 점수 구성 | 비용 합 |
|---|---|---|---|
| 1단계 | 8장 | 0점 일곱 · 1점 하나 | 3~5개 |
| 2단계 | 6장 | 1 · 1 · 2 · 2 · 2 · 3점 | 5~8개 |
| 3단계 | 4장 | 3 · 4 · 4 · 5점 | 7~14개 |

귀족 10명 중 다섯은 **두 색 4장씩**, 다섯은 **세 색 3장씩**을 요구한다.
이름과 그림은 원작을 따르지 않고 새로 지었다.

그림은 전부 `index.html` 안에 **인라인 SVG**로 그려 두고 `<use>` 로 꺼내 쓴다.
이미지 파일이 하나도 없어서 요청도 한 번뿐이고, 어느 크기로 늘려도 깨지지 않는다.

## 처음이면

처음 열면 **여섯 장짜리 안내**가 먼저 뜬다. 무엇이 목표인지, 차례에 뭘 하는지,
0점 카드를 왜 사는지, 귀족이 어떻게 오는지까지 그림과 함께 넘겨 보면 된다.
한 번 보면 다시 뜨지 않고, 홈의 `처음이면 — 어떻게 하는 게임인지 보기` 로 언제든 다시 열 수 있다.

판 위쪽의 **도우미**를 켜 두면(처음 온 사람은 켜진 채로 시작한다) 매 차례

- 지금 **무엇을 누르면 되는지** 한 줄로 알려주고,
- 추천하는 카드·보석·더미에 **금색 점선**을 둘러 준다.

문구는 봇이 쓰는 판단을 그대로 돌려서 만든다. 그래서 "왜 그게 좋은지"까지 한마디 붙는다 —
`다이아몬드 카드가 늘면 앞으로 사는 카드가 계속 싸집니다` 처럼.
뭔가를 고른 순간에는 점선이 사라져서, 지금 하려는 일에만 집중할 수 있다.

익숙해지면 스위치를 끄면 된다. 한 번 끄면 그 선택을 기억한다.
오른쪽 위 `도움말` 에는 규칙과 **화면 보는 법**(카드 어디에 뭐가 적혀 있는지)이 정리돼 있다.

## 조작

- 아래 **보석 더미**를 눌러 고른다. 한 색을 고른 상태에서 그 색을 다시 누르면 **2개**가 된다
  (4개 이상 남아 있을 때만). 고르면 아래 띠에 `가져오기` 가 뜬다.
- **카드를 누르면** 아래 띠에 `사기` `킵하기` 가 뜬다. 지금 살 수 있는 카드는 **초록 테두리**,
  이미 감당되는 비용 칩은 **흐리게** 표시된다.
- 카드는 실물처럼 **위쪽 띠에 점수와 보석 문양**, **왼쪽 아래에 비용 칩**이 놓인다.
  그림은 단계마다 다르다 — 1단계 광산, 2단계 세공 공방, 3단계 왕관.
- 왼쪽 **더미**를 누르면 안 보고 한 장 킵한다.
- 칩이 10개를 넘으면 **내 칩 칸**을 눌러 버릴 것을 고른다. 칸 전체가 버튼이고, **같은 칸을 두 번 누르면 그 색을 2개** 버린다.
  다 고른 뒤 또 누르면 하나씩 되돌아가고, `다시 고르기` 로 한 번에 비울 수도 있다.
  도우미가 켜져 있으면 무엇을 버릴지 짚어 주고 `추천대로 버리기` 한 번으로 끝낼 수도 있다.
  이 단계에서는 내 칩 줄이 아래 조작 판에 가리지 않도록 화면이 알아서 그 위치까지 올라간다.
- 귀족 조건을 둘 이상 동시에 채우면 위에서 한 명을 고른다.

내 킵 카드는 나만 앞면으로 보인다. 남이 더미에서 가져간 킵은 **단계만** 보인다.

## 테마

오른쪽 위 슬라이드 스위치로 **밝은 테마 / 어두운 테마**를 바꾼다.
처음 열 때는 기기 설정(`prefers-color-scheme`)을 따르고, 한 번 바꾸면 그 선택을 기억한다.
스타일시트보다 먼저 도는 짧은 스크립트가 `<html data-theme>` 를 미리 박아 둬서 첫 화면이 번쩍이지 않는다.

색은 전부 CSS 변수 한 벌이라 `:root[data-theme="light"]` 블록만 갈아끼우면 테마가 바뀐다.
다만 **카드와 보석 색은 두 테마에서 똑같이 둔다** — 그건 꾸밈이 아니라 게임 정보라서 바뀌면 헷갈린다.

## 실행

```
npm install
npm start            # node server.js — http://localhost:8874
```

`server.js` 는 `public/` 을 정적 파일로 내주고 `/ws` 로 소켓을 받는 Node 서버다. 로컬 개발과 테스트용이고,
실제 서비스는 Cloudflare(`worker.js`)에서 같은 `game.js` 로 돈다. 데스크톱 Chrome 권장. 모바일 폭에 맞춰 만들었다.

타이틀에는 `시작하기` · 가이드 버튼과 **열린 방** 목록을 둔다. `시작하기` 를 누르면 고르는 화면이 나온다.

- **혼자 연습** — 봇 1~3명과. 실력 3단계. 서버를 거치지 않고 이 브라우저에서 판이 돈다.
- **방 만들기** — 4자리 코드가 나온다. 코드나 초대 링크로 친구가 들어온다. 비공개로 만들 수도 있다.
- **참가** — 코드를 넣거나, 타이틀의 열린 방 목록에서 고른다.

## 대기실

- **초대 링크 복사** — `?room=CODE` 주소다. 이 링크로 열면 고르는 화면에 코드가 채워져 있다.
- **열린 방** — 시작 전이고 자리가 남은 공개 방을 타이틀에서 6초마다 새로 본다. 누르면 코드를 채워 고르는 화면으로 간다.
- **비공개 방** — 만들 때 고르거나 방장이 대기실에서 켠다. 목록에 안 보이고 코드·링크로만 들어온다.
- **봇 추가 · 내보내기 · 봇 실력** — 방장만. 봇 실력은 방 설정이라 그 방의 봇 모두에 적용된다.
- **채팅** — 사람이 둘 이상이면 오른쪽 아래에 뜬다. 서버가 같은 방에만 돌려주고 저장하지 않는다.
  접어 둔 동안 온 말은 빨간 숫자 · 말풍선 · 탭 제목의 `(n)` 세 군데로 알린다.
- **새로고침** — 탭마다 자리표(`sessionStorage`)를 적어 두어, 새로고침해도 같은 자리로 돌아온다.
  같은 자리를 다른 탭이 이어받으면 먼저 탭은 쉬고(4001), 누르면 다시 가져온다.
- **방장이 나가면** — 끊긴 방장은 20초 기다렸다가 붙어 있는 사람에게 넘긴다. 그 안에 돌아오면 그대로 방장이다.
  모두 끊겼다가 먼저 돌아온 사람이 방장을 맡는다. 판은 방장과 상관없이 이어진다.
- **판 중에 끊기면** — 그 사람 차례가 오면 20초 기다린다. 돌아오지 않으면 판에서 빠지고(쥔 보석은 은행으로) 남은 사람끼리 계속한다.
  판 위쪽 `나가기` 를 누르면 곧바로 빠진다.
- **판이 끝나면** — 방장이 `한 판 더` 를 누르면 모두 대기실로 돌아간다.

## 배포

Cloudflare Workers 무료 플랜. `wrangler.toml` 에 설정이 다 들어 있다.
화면 파일(`public/`)은 정적 자산으로, 소켓(`/ws`)과 상태 확인(`/healthz`)만 Durable Object 하나(`main`)로 간다.

```
./bump.sh              # 자산 URL 의 ?v= 를 내용 해시로 갱신
npx wrangler login     # 처음 한 번
npx wrangler deploy
```

무료 한도는 "객체가 켜져 있는 시간"이 먼저 찬다. 그래서

- 탭은 25초마다 ping 을 보내고, 2분 반 넘게 소식이 없는 소켓은 끊긴 것으로 친다.
- 20분 동안 아무 조작이 없는 소켓은 서버가 닫는다(4000). 화면은 아무 곳이나 누르면 다시 붙는다.
  대기실 자리는 이때 지우지 않는다(사람이 나간 게 아니라서).
- 방도 소켓도 없으면 청소 타이머까지 멈춰 객체가 잠든다. 혼자 하기를 누르면 방 목록용 연결도 내려놓는다.

`/healthz` 는 `{"ok":true,"rooms":N,"sockets":N}` 을 돌려준다.

## 통신

**서버가 심판이다.** 판(더미 · 은행 · 자리 · 차례)과 봇은 전부 `game.js` 가 쥐고, 규칙 판정은 `rules.js` 가 한다.
화면은 `{t:'act', action, args}` 로 하고 싶은 행동만 보내고, 규칙에 어긋나면 이유가 돌아와 토스트로 뜬다.
신원은 소켓이 정하므로 남의 차례를 가로챌 수 없다.

사람마다 `viewFor()` 로 볼 수 있는 만큼만 잘라서 보낸다. 스플렌더는 숨기는 정보가 거의 없어서,
감춰지는 것은 **더미의 순서**와 **남이 더미에서 가져간 킵 카드**뿐이다. 그 둘은 아예 전송되지 않는다.
예전(PeerJS P2P)에는 방장이 더미 순서를 볼 수 있었는데, 이제는 아무도 못 본다.

봇이 곧바로 두면 방금 무슨 일이 있었는지 읽기 전에 판이 바뀐다. 서버는 기록의 마지막 줄을 읽을 시간
(0.8초 + 글자당 0.07초, 최소 1.4초)만큼 다음 봇 수를 미룬다. 그 수를 둔 사람 말고 볼 사람이 없으면 0.6초만 쉰다.

**혼자 하기는 브라우저에서 돈다.** 서버 한도를 아끼려고, 봇과 하는 판은 예전처럼 `app.js` 가 같은
`rules.js` · `ai.js` 로 직접 돌린다. 온라인 판과 같은 `applyView` 로 그리므로 판 화면 코드는 하나다.

### rules.js · ai.js 를 양쪽에서 쓰는 법

원본은 저장소 루트에 하나씩만 있다. 둘 다 끝에서 `module.exports` 가 있으면 그리로, 없으면 `window.Rules` · `window.AI` 로 내보낸다(UMD).

- 서버 — `game.js` 가 `require('./rules')` · `require('./ai')` 로 부른다. wrangler 가 묶을 때 그대로 따라 들어간다.
- 화면 — `public/rules.js` · `public/ai.js` 는 `../rules.js` · `../ai.js` 를 가리키는 **심볼릭 링크**다.
  Node 서버는 링크를 따라 읽고, wrangler 는 자산을 모을 때 링크를 따라가 원본 내용을 올린다. 복사본도 빌드도 없다.
  `test/smoke.js` 가 `/rules.js` · `/ai.js` 응답이 루트 원본과 글자 하나까지 같은지 확인한다 — 배포본에 대고도 돌려 볼 것.

## 파일

| 파일 | 역할 |
|---|---|
| `rules.js` | 규칙 엔진. 순수 함수. 네트워크도 UI도 모른다. 서버와 화면이 같이 쓴다 |
| `ai.js` | 봇. 카드 값어치를 '보석 몇 개어치'로 환산해 고른다. 서버와 화면이 같이 쓴다 |
| `game.js` | 방 관리와 온라인 판 진행. 통신 방식은 모른다 |
| `worker.js` | Cloudflare Worker + Durable Object. 소켓을 `game.js` 에 잇는다 |
| `server.js` | 같은 `game.js` 를 Node `ws` 로 띄우는 로컬 서버 |
| `wrangler.toml` | Cloudflare 설정. 자산 `public/`, `/ws` · `/healthz` 만 Worker 로 |
| `public/index.html` `style.css` `app.js` | 화면. 혼자 하기 진행, 온라인 연결 · 대기실 · 채팅 |
| `public/rules.js` `public/ai.js` | 루트 원본을 가리키는 심볼릭 링크 |

## 봇

카드 한 장의 값어치를 **보석 몇 개어치**로 환산한다.
0점짜리 1단계 카드도 값이 있다 — 판이 끝날 때까지 계속 비용을 깎아주고 귀족도 불러오기 때문이다.
그래서 초반에는 싼 카드를 부지런히 사고, 누가 11점을 넘기면 그때부터는 **점수만** 본다.

보석을 집을지 카드를 살지는 이렇게 견준다.

- 사면 → 그 카드 값어치를 **이번 차례에 통째로** 얻는다
- 집으면 → 목표 카드에 `집는 개수 / 남은 개수` 만큼 다가간다

둘을 비교해서 큰 쪽을 고른다. 칩이 10개면 집어봐야 도로 버리므로 사는 쪽으로 크게 기운다.

실력을 낮추면 **가끔 아무 수나 둔다.** 판단을 조금씩 흐리게 만드는 것보다 이쪽이 실제로 약하다.
어려움은 쉬움에게 70%, 보통에게 54%로 이긴다.

## 테스트

```
npm test                                   # 아래 셋을 차례로
node rules.test.js
node ai.test.js
node test/flow.js                          # 서버를 8874 에 SPLENDOR_FAST=1 로 띄워 시나리오를 돈다
node test/smoke.js http://127.0.0.1:8874   # 떠 있는 서버(어느 것이든) 확인
```

- 규칙 엔진 **97개** — 카드 구성(다섯 색 대칭 · 자기 색 요구 없음), 보석 집기 제한, 칩 10개,
  보너스 할인과 황금, 킵 3장과 뒷면 은닉, 귀족 자동/선택, 마지막 라운드와 동점 처리,
  나간 사람 건너뛰기, 그리고 **무작위 500판 완주** (매 수마다 칩 총량 보존 · 칩 10개 · 점수 합계 검사)
- 봇 **16개** — 살 수 있으면 사는지, 0점 엔진 카드도 초반에 사는지, 막판에 점수로 갈아타는지,
  넘치는 칩을 정확히 버리고 황금을 남기는지, 실력을 낮춰도 규칙에 걸리지 않는지,
  그리고 **어려움이 쉬움을 이기는지**
- 서버 시나리오 **23개** (`test/flow.js`) — 방 만들기 · 참가 · 같은 이름 · 채팅, 방장만 되는 조작,
  비공개 방이 목록에서 빠지는지, 봇 실력 설정, 사람마다 다른 시야(더미 순서 · 남의 뒷면 킵이 안 새는지),
  남의 차례 · 규칙 위반 거절, 새로고침으로 자리 되찾기와 4001, 방장이 끊기면 유예 뒤 넘겨지기 ·
  유예 안에 돌아오면 지키기 · 모두 끊겼으면 먼저 온 사람, 끊긴 사람 차례에 판에서 빠지기,
  판 중 나가기(보석이 은행으로), 한 판 더, 사람 하나 + 봇 셋 **한 판 완주**(매 시야마다 칩 총량 검사).
  `SPLENDOR_FAST=1` 이면 봇 뜸 · 읽는 시간 · 유예(300ms)가 짧아진다. 실제 유예가 20초인지는 따로 확인한다.
- 연결 확인 **11개** (`test/smoke.js`, `IDLE=1` 이면 12개) — 화면 파일, 링크로 둔 `rules.js` · `ai.js` 가
  원본과 같은지, `/healthz`, 만들기 · 참가 · ping · 채팅 · 목록과 비공개 · 한 수 · resume · 4001 · 나가기.

wrangler dev 에 대고 돌릴 때는 포트를 따로 준다.

```
npx wrangler dev --port 8875 --var SPLENDOR_FAST:1         # 한 창에서
node test/smoke.js http://127.0.0.1:8875                   # 다른 창에서
PORT=8875 node test/flow.js                                # 이미 떠 있는 서버에 붙는다
npx wrangler dev --port 8875 --var IDLE_MS:6000 --var SWEEP_MS:500
IDLE=1 node test/smoke.js http://127.0.0.1:8875            # 조작 없는 소켓이 4000 으로 닫히는지
```

## 알려진 제약

- 관전 모드 없음. 판이 시작되면 새로 들어올 수 없다.
- 판에서 빠진 사람은 그 판에 다시 들어올 수 없다. 끝날 때까지 지켜보기만 한다.
- 무를 수 없다. 카드를 누르고 `사기` 를 누르면 그대로 나간다.
- 방은 서버 메모리에만 있다. 배포하거나 객체가 다시 켜지면 열린 방이 사라진다.

## 연출 속도 재기

봇끼리 한 판을 끝까지 두면서 "방금 둔 수" 알림이 몇 초씩 떠 있었는지 재고,
사람이 읽기에 너무 빠른 곳을 찾아 준다. 헤드리스 크롬의 가상 시간으로 돌리므로
실제 기다림 없이 설계된 속도 그대로 측정된다.

```bash
PORT=8799 node server.js         # 먼저 서버를 띄워 두고 (혼자 하기라 판은 브라우저에서 돈다)
sh qa/run.sh 4
```

화면 쪽 조각(`qa/scene.js`)은 `public/qa/` 에 있고, `?qa=pace` 로 들어올 때만 불러온다.

읽는 속도는 한글 짧은 문구 기준 **0.8초 + 글자당 0.07초**로 잡았다.
알림을 띄우는 시간도 같은 식으로 계산하므로(`readMs`), 문구가 길어지면 그만큼 오래 머문다.
